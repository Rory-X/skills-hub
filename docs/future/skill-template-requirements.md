# Skill Templates / Skill 模板需求基线

## 状态

- 决策状态：已确认，进入实现与验收。
- 替代文档：[Skill Profile / 配置方案后续需求记录](./profile-requirements.md)。
- 本文是 Skill Templates 第一版的产品、领域与验收基线。

## 产品定义

Skill Template 是**有名称和可选说明的一组无序 Skill 引用**。

它用于从 Skill 库中归档一套可复用的 Agent 能力，并一次性应用到项目。模板不包含 Skill 实体副本，不规定 Skill 的调用顺序、调用条件或自动执行步骤。

标准链路：

```text
导入 Skill 库 -> 选择 Skill 制作模板 -> 项目复用模板
```

## 范围与约束

1. 模板只应用于项目，不支持全局模板。
2. 一个项目同一时间最多绑定一个模板；切换模板是替换模板来源，不是叠加多个模板。
3. 一个 Skill 可以被多个模板引用；同一模板内不能重复引用同一 Skill。
4. 模板至少包含一个 Skill，名称去除首尾空白后不能为空，名称不区分大小写且唯一。
5. 模板只有名称、可选说明、同步模式和 Skill 引用集合，不保存目标 Agent 列表。
6. 模板中的 Skill 使用项目当前启用的 Agent 配置；项目 Agent 配置变化后重新协调模板分配。
7. 模板不复制 Skill 实体。Skill 库中的实体仍是内容来源，实际 Agent 目录沿用现有的符号链接、Windows junction、实体复制三级回退策略。
8. Skill Hub 的内部库目录本身不代表分配。只有在真实 Agent 配置目录中存在有效目标时，Agent 才应获得该 Skill。

## 同步模式

同步模式在创建模板时选择，创建后不可修改。

### Live / 自动同步

- 用户选择 Live 即同意后续静默同步。
- 模板 Skill 成员变化后，所有已绑定项目自动协调到最新成员集合。
- 名称或说明变化仍产生修订，但不会触发项目 Skill 协调。
- 单个项目或单个 Skill 同步失败不能阻止其他项目或 Skill 继续同步。

### Snapshot / 固定快照

- 项目应用模板时固定到当时的修订。
- 模板后续变化不会静默修改已绑定项目。
- 用户在项目中显式执行更新后，项目才采用模板当前修订。

## 修订与回滚

1. 创建模板生成第一个修订。
2. 每次保存都生成新修订，包括仅修改名称或说明。
3. 修订保存当时的名称、说明和 Skill 引用快照。
4. 回滚不会重写历史，而是以目标历史内容创建一个新的当前修订。
5. Live 模板回滚导致成员变化时，按 Live 规则静默协调项目；Snapshot 项目保持原应用修订，直到显式更新。

## 项目应用与来源

应用或切换模板前，界面显示 Skill 集合差异：新增、移除和保留。

项目 Skill 的意图来源分为：

- `manual`：用户直接在项目中引入。
- `template`：由当前项目模板引入。

同一个项目 Skill 可以同时具有两种来源。协调时按来源并集计算：

- 删除或切换模板只移除旧模板来源。
- 只要仍有任一有效来源，项目 Skill 和其有效 Agent 分配就保留。
- 解绑模板时，用户可以选择删除模板来源，或把模板来源转换为手动来源后保留。
- 项目已有原生同名 Skill 与库中 Skill 冲突时，记录失败并允许用户明确选择使用库版本或保留项目原生版本。

若同一 Agent 的全局有效分配已经满足项目需求，不额外创建项目实体目标，但保留正确的项目来源与生效关系。

## 模板生命周期

### 归档

- 归档模板继续服务已经绑定的项目。
- 归档模板不能新应用到其他项目。
- 归档不是删除，可以重新恢复。
- 模板页默认隐藏归档项，可由用户显式显示。

### 删除

- 仍有项目绑定时，模板删除必须被阻止。
- 删除未绑定模板时，同时删除其当前成员、修订和相关模板状态。
- 删除 Skill 时，当前模板成员或当前项目来源中的引用会阻止删除，并指出阻塞来源。
- 仅存在于历史修订中的 Skill 引用不阻止 Skill 删除。

### Skill 停用与恢复

- 停用 Skill 保留模板成员关系，即保留用户意图。
- 停用会原子地移除该 Skill 的实际 Agent 目标和有效分配；中途失败时回滚文件与数据库状态。
- 停用的 Skill 不参与模板实际同步，并清除由它造成的模板失败聚合。
- 已在模板中的停用 Skill 可以继续留在模板内，但不能把新的停用 Skill 加入模板。
- 重新启用后，系统按现有全局、项目和模板意图进行最终一致恢复；冲突或恢复失败必须记录为失败，不能当作已跳过成功。

## Agent 目录与共享路径

Skill Hub 只根据实际分配写入真实 Agent 配置路径，不把内部库当作隐式 Agent 配置。

部分工具适配器可能共享同一个底层 Skill 目录。因此，为其中一个 Agent 勾选分配后，读取同一目录的其他 Agent 也可能看到该 Skill。这是第一版接受的适配器事实，项目界面需要提示额外可见性；它不改变逻辑分配记录，也不通过复制 Skill 实体规避。

系统在启动及工具配置变化后执行保守的孤儿链接清理：

- 只检查 Agent Skill 目录的直接子项。
- 只删除指向已知中心 Skill、但已经没有有效分配的符号链接。
- 不删除普通目录、指向未知或外部位置的链接、嵌套链接及中心库目录本身。

## 失败与可见状态

正常同步、同步中、已同步、Snapshot 较旧等状态不以状态徽标持续暴露。只有未成功同步的状态需要显式显示。

失败按项目、模板、Skill、Agent 和失败类型持久化，支持：

- 查看失败原因。
- 重试项目模板同步。
- 处理项目原生 Skill 冲突。
- 在后续成功、停用 Skill、解绑或切换模板后清理已经失效的失败。

## 数据模型

SQLite schema v10 使用以下实体：

| 实体 | 责任 |
| --- | --- |
| `skill_templates` | 模板身份、不可变模式、归档状态和当前修订 |
| `skill_template_items` | 当前无序 Skill 引用集合 |
| `skill_template_revisions` | 名称、说明的历史快照 |
| `skill_template_revision_items` | 每个修订的 Skill 引用快照 |
| `project_template_bindings` | 项目唯一模板绑定、已应用修订和聚合失败 |
| `project_skill_origins` | 项目 Skill 的 `manual` / `template` 意图来源 |
| `project_template_overrides` | 项目原生版本冲突选择 |
| `project_template_failures` | 可重试的 Skill / Agent 级失败 |

迁移时，已有启用的项目 Skill 链接转成 `manual` 来源，保证升级不改变用户现有项目配置。

## 用户界面

1. 主导航提供 Templates 页面。
2. 用户可从模板页创建模板，也可在 Skill 库多选 Skill 后直接进入模板创建。
3. 创建时填写名称、可选说明，选择不可逆的 Live 或 Snapshot 模式，并选择至少一个可用 Skill。
4. 模板详情支持编辑、归档/恢复、删除、查看修订及回滚。
5. 项目详情支持预览并应用/切换模板、解绑、更新 Snapshot、重试失败和解决冲突。
6. 项目 Skill 列表显示其模板来源，并提示共享 Agent 目录造成的额外可见性。
7. 所有用户可见文字提供英文和中文翻译；桌面和窄屏布局均可完成核心操作且无文本溢出。

## 不在第一版范围

- 全局应用模板。
- 同一项目叠加多个模板。
- 模板级目标 Agent 集合。
- Skill 调用顺序、条件、依赖编排或自动执行步骤。
- 从项目反向自动生成模板。
- 通过复制 Skill 实体制造模板或隔离共享 Agent 目录。
- 远端模板发布、团队共享和跨设备云同步。

## 验收标准

- 创建 Live / Snapshot 模板后不能修改模式，名称唯一校验和至少一个 Skill 校验生效。
- 每次保存创建修订；回滚创建新修订且不破坏历史。
- Live 成员变化静默同步所有绑定项目，元数据变化不重新协调成员。
- Snapshot 保持应用修订，只有显式更新才采用最新修订。
- 每个项目最多绑定一个模板；应用、切换、解绑和保留为手动来源的结果符合来源并集规则。
- 归档模板不能新应用但继续服务已绑定项目；绑定中的模板不能删除。
- 当前模板/项目引用阻止 Skill 删除，历史修订引用不阻止。
- Skill 停用原子移除实际目标并保留模板意图，重新启用恢复；冲突以失败呈现。
- 未分配 Skill 不出现在真实 Agent 配置中；保守孤儿链接清理不触碰用户普通目录或外部链接。
- 一项同步失败不阻止其他项目、Skill 或 Agent；UI 只显式突出失败状态并提供处理入口。
- 前后端 DTO、Tauri 命令、数据库迁移和中英文 UI 完整接线。
- `npm run check` 全部通过，并完成桌面与窄屏核心流程的视觉验收。
